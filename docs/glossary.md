# 用語集

このプロジェクトで使う言葉の定義です。状態の表記は [README](../README.md#状態の読み方) を参照してください。

## レイヤーとテスト

| 用語 | 定義 | 状態 |
|---|---|---|
| ビジネスレイヤー | 業務の流れを扱う層。ビジネスワークフローとビジネスシナリオを持つ | 【確定】 |
| 機能レイヤー | 作業の内部を扱う層。マニュアル作業は本来「機能」ではないが、レイヤー名としてはこの名前を使う | 【確定】 |
| ビジネステスト | ビジネスレイヤーに対するテスト。作業をまたいで業務が通ることを確かめる | 【確定】 |
| 機能テスト | 機能レイヤーに対するテスト。作業の内部の振る舞いを確かめる | 【確定】 |

## ビジネスレイヤーの要素

| 用語 | 定義 | 状態 |
|---|---|---|
| ビジネスワークフロー | 作業を節点とし、順序・分岐・並行で業務の流れを表したもの | 【確定】（並行を含むこと） |
| 業務フロー | ビジネスワークフローのうち、本来の業務の流れを表すもの | 【提案】（種別の区分） |
| 反映確認フロー | マスターメンテナンスなどの変更が、該当する業務へ反映されることを確認するためのフロー。厳密には業務フローではないが、定義して管理する | 【確定】（呼称は仮） |
| ビジネスシナリオ | ビジネスワークフローを通す経路と、その目的・期待結果 | 【提案】 |

## 作業

| 用語 | 定義 | 状態 |
|---|---|---|
| 作業 | ビジネスワークフローを構成する単位。次の3種類がある | 【確定】 |
| ユーザー作業 | ユーザー操作を伴う作業。内部はステートマシン図で表す | 【確定】（呼称は仮） |
| サービス作業 | システムが単独で実施する作業（バッチ、サービスなど）。内部はUMLのアクティビティ図で表す | 【確定】 |
| マニュアル作業 | システムを利用しない作業。内部はUMLのアクティビティ図で表す。結果がビジネスフローに影響しうるため、内部の分析・設計を行う | 【確定】 |
| 結果 | 作業が終わったときの、名前付きの終わり方（正常完了、取消など）。上位の分岐はこの名前を参照する | 【提案】 |
| include | ある作業が別の作業を必ず呼び出す関係 | 【確定】（概念の導入） |
| extend | 条件が成り立つときだけ、別の作業が基本の作業の拡張点に差し込まれる関係 | 【確定】（概念の導入） |

## 共通の要素

| 用語 | 定義 | 状態 |
|---|---|---|
| アクター | 作業の担い手。両レイヤーで共有する | 【提案】 |
| ビジネスオブジェクト | 業務が扱う対象（受注、請求など）。ワークフローの設計時、作業の設計時のいずれからでも導出でき、手順や手法は限定しない | 【確定】（導出すること） |
| 生成 | 作業がビジネスオブジェクトを作る関係 | 【提案】 |
| 状態変更 | 作業がビジネスオブジェクトの状態を変える関係 | 【提案】 |
| 参照 | 作業がビジネスオブジェクトを読む関係。反映確認の漏れの検査に使う | 【確定】 |

## 評価に関する用語

| 用語 | 定義 | 状態 |
|---|---|---|
| シナリオ | モデル上の経路と、その目的・期待結果を組にしたもの | ucspecから継承 |
| 網羅率 | モデルから数え上げた対象（状態、遷移、経路など）のうち、シナリオが通した割合 | ucspecから継承 |
| 未網羅の評価 | 未網羅の経路ごとに、シナリオの追加、既存シナリオでの代表、禁止のいずれかを理由付きで判断すること | ucspecから継承 |
| 決定論的 | 同じモデルからは、いつ誰が実行しても同じ検査結果と評価が得られること | 【確定】 |

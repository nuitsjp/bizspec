# 検査と評価

モデルに対して行う検査と、テストの十分性の評価についての整理です。

## 1. 基本方針

- ucspecが機能テストに対して行う評価と同等の評価を、ビジネステストにも適用できるようにします。【確定】
- 検査と評価は決定論的に行います。【確定】

「同等の評価」が成り立つには、ビジネスレイヤーにも経路を数えられるモデルが必要です。ビジネスワークフローを、作業を節点、順序と分岐を辺とするグラフとして持つことで、これを満たします。

## 2. 機能レイヤーの評価

ucspecの評価をそのまま使います。READMEによれば、ucspecは次の検査と網羅率を持ちます。

| 分類 | 内容 |
|---|---|
| 構造検査 | 名前と参照、開始、ディシジョン、ユースケースの完了可能性、到達できない状態・遷移の警告 |
| シナリオ検査 | イベントと分岐名の手順、アクターの権限、範囲、ユースケースの終了 |
| 網羅率 | 末端状態、複合状態、遷移、連続2遷移、プライムパス、上限付き完了パス |
| 未網羅の評価 | シナリオの追加、既存シナリオでの代表、禁止の判断と、その理由 |

サービス作業とマニュアル作業の内部はアクティビティで表すため、アクティビティに対する検査と網羅率の定義が別に必要です。【未決】

## 3. ビジネスレイヤーの評価

### 網羅率【提案】

機能レイヤーの指標を、ビジネスワークフローのグラフに当てはめます。

| 機能レイヤーの指標 | ビジネスレイヤーでの対応 |
|---|---|
| 状態 | 作業 |
| 遷移 | 作業から作業への遷移（結果による分岐を含む） |
| 連続2遷移 | 連続する2つの遷移 |
| プライムパス | プライムパス |

### 並行の扱い【提案】

並行を受け入れることは確定しています。その場合、経路が単純な列ではなくなるため、網羅率の定義に手を入れる必要があります。現在の案は次のとおりです。

- 並行する枝の実行順（インターリーブ）は数えない。
- シナリオは、各枝でどの経路を通ったかの組で表す。
- 網羅率は、作業、遷移、並行区間ごとの枝の組み合わせで測る。
- 構造検査に、待ち合わせが成立しないこと（合流に届かない枝がある、デッドロックする）の検出を加える。

実行順に業務上の意味がある場合は、並行ではなく明示的な分岐として書く前提です。

### includeされた作業の数え方【確定】

includeされた作業は、呼ぶ側の網羅率では結果だけを分岐として数えます。呼ばれる作業の内部は、その作業自身のシナリオで一度だけ評価します。

展開して数えると経路が組み合わせで膨らみ、同じ経路を何度も数えることになるためです。

extendについては、拡張なしの経路と拡張ありの経路の両方がシナリオで通されているかを評価します。【提案】

### include・extendの構造検査【提案】

- includeの循環
- 呼ばれた作業の結果のうち、呼ぶ側が受け止めていないもの
- 存在しない拡張点への参照

## 4. ビジネスオブジェクトを使う検査

### 反映確認の漏れ【確定】

作業とビジネスオブジェクトの「参照」の関係を使い、次の検査を行います。

1. マスターを変更する作業と、そのマスターを参照する作業の組を列挙する。
2. その組のうち、反映確認フローで通されていないものを未網羅として示す。

### 状態を使う検査【提案】

ビジネスオブジェクトに状態を持たせる場合、次の検査ができます。

- 作業の前提となる状態を、先行するどの経路も作っていない。
- どの作業も作らないオブジェクトを使っている。
- 到達しない状態がある。
- 並行する枝が同じオブジェクトの状態を変えている。

### ライフサイクルの網羅率【提案】

ワークフローの経路網羅とは別の軸として、オブジェクトの状態と状態変化がシナリオでどこまで通されたかを測ります。

## 5. 二層の責務の分担

| | 確かめること | 問わないこと |
|---|---|---|
| ビジネステスト | 作業をまたいで業務が通ること | 作業の内部の経路 |
| 機能テスト | 作業の内部の振る舞い | 業務の流れ |

マニュアル作業は機能レイヤーに実装を持ちません。内部のアクティビティは分析・設計の対象ですが、システムによる検証手段がないため、検証の扱いを決める必要があります。【未決】

## 6. 評価の限界

次の点に注意が必要です。詳しくは [目的と保証範囲](purpose.md) を参照してください。

- 現在の決定事項で評価できるのは、モデルに対するシナリオ定義の網羅性です。実テストの存在や合否は評価していません。
- 網羅率はモデルに対する割合です。モデルに漏れがあれば、網羅率が100%でも漏れは残ります。
- 属性に依存する条件や境界値は、評価の対象外です。

# 目的と保証範囲

## 目的

bizspecの目的はシステム開発です。扱うのは業務改善そのものではなく、対象システムを開発するためのビジネス設計です。

> このシステムで業務が回ることを、どこまで確かめれば十分と言えるのか。
> その判断を、勘ではなく業務のモデルに基づいて数えられるようにする。

「テストは十分か」という問いを、次の2つに置き換えます。

- 業務として起こりうる流れのうち、どれを確かめ、どれを確かめていないか。
- 確かめていない流れには、確かめなくてよい理由があるか。

## 進め方

1. モデルから文書を生成し、人が読んでモデルの妥当性に合意する。
2. 合意したモデルから、確かめるべき経路を決定論的に導く。
3. 確かめていない経路ごとに、シナリオを追加するか、既存のシナリオで代表させるか、禁止するかを理由付きで判断する。

## 保証しないこと

- **実際のテストの存在と合否**：評価できるのは、モデルに対するシナリオの網羅性です。実テストとの対応付けは未決です（[O-02](open-issues.md#o-02-実テストとの対応付け)）。
- **モデルの正しさ**：モデルに業務の流れが漏れていれば、網羅率が100%でも漏れは残ります。モデルの妥当性は、文書を読んだ人の合意だけが保証します。
- **データの中身と業務ロジック**：規定するのは、流れ・状態・結果といった振る舞いの骨格です。属性に依存する条件や境界値は、実装とそのテストが受け持ちます。
